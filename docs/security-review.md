# Security review (web app + core)

Scope: `apps/web` (server actions, REST `/api/v1`, pages) and `packages/core`. Auth wiring (`auth.ts`, `/api/auth`, OAuth consent), MCP, db and docker were reviewed read-only and are listed under "Open items".

## Verified OK (no change needed)

- Every server action derives its Ctx with `getCtx(slug)` (session -> membership of that org). Client-supplied `slug`/ids are never trusted for authorization; ids are resolved by core inside `ctx.orgId`.
- Core reads/writes filter by `org_id` (`scoped()` / explicit `orgId`) incl. update/delete by id; `test/security.test.ts` adds a cross-org write matrix on top of the existing isolation tests.
- Role checks are in the runner (`minRole`), not only the UI. Viewers cannot run any command; org/brand/modules/calendar/terminology/people/teams commands are `admin` (tested).
- API keys: `mk_live_<random>`, only the sha256 hash is stored, plaintext returned once, redacted from audit and `request_log`.
- No `dangerouslySetInnerHTML`/`innerHTML` anywhere; descriptions and markdown-like text render as React text. Recap email HTML escapes every interpolated value and validates the accent color.

## Open items (not edited: owned by the parallel agent / out of scope)

- Resolved in the final hardening pass: findings 9-13 above (auth secret fallback, invite claiming, open redirect, security headers). CSP still allows inline scripts (Next bootstrap); a nonce-based CSP via `proxy.ts` would tighten it at the cost of fully dynamic rendering.
- Invite links are bearer credentials: whoever holds the link (before it is used or expires) can join. Email verification was not added.
- Rate limiting is per process (in memory); use a shared store when running several instances.
- Members can read other agents' key prefixes and the full audit log (read-only by design).
